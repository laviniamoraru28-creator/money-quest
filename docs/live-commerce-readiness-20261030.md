## What is implemented

- Off remains the default. Sandbox continues to accept test credentials. Live mode requires a restricted live key, HTTPS origin, declared hosting document root, private release manifest and authenticated TLS SMTP settings. Test/live session IDs, events and stored orders are separated; live orders live under the private base directory's `live` subdirectory.
- A live Checkout Session is created only after the account matches the release account ID, charges and payouts are enabled, the selected live Price is active/one-time/GBP/the exact expected amount and tax-inclusive, the private archive matches its approved SHA-256/byte count, and SMTP authentication succeeds. Adaptive pricing is explicitly disabled to preserve the quoted fixed GBP total. There are no subscriptions or extra charges.
- Current live storefront support follows the existing public English-only gate. Closed/sandbox multilingual drafts stay intact. The live UI replaces test/proposed-price wording, displays configured seller identity/address/contact/tax information, requires a fourth initially unchecked full-terms/English-file acknowledgement, and links the full terms and purchase privacy policy. It refuses an unprepared non-English live presentation rather than displaying a mixed-language contract. Live interface/policy translations are therefore still needed before activating other languages.
- Each live checkout stores an immutable private snapshot before opening Stripe: product description/pages/inclusions, exact amount/price, merchant/account, complete terms/version, purchase privacy/tax statement and content-addressed archive. Stripe metadata links the session to that snapshot. Later release edits cannot rewrite the existing purchase's accepted contract or point it at a replacement archive.
- Both signed paid completion and asynchronous-success webhooks fulfil independently of a returning browser. The application re-fetches the paid session and expanded charge, checks amount/currency/price/consents/contract/account/mode, rejects refunds/partial refunds/disputes, saves the idempotent private order, then sends the adult checkout email its full confirmation and recovery link. Browser verification is an additional retry path, not the only fulfilment trigger.
- Confirmation includes full product details, seller, inclusive total, consent acknowledgements, complete accepted terms and purchase privacy text. The SMTP recipient comes from Stripe and is not stored in order JSON. SMTP and Stripe nevertheless process adult personal data. The app does not collect child billing data or activity responses.
- SMTP accepted/sent state is stored privately. Failure returns a retryable fulfilment error; payment is not recreated. A scheduler command retries existing pending orders after rechecking payment. Order/download endpoints refuse access while the live confirmation remains pending, and all file access rechecks payment and archive integrity. Download links remain signed, private, expiring and reusable.
- Persistent filesystem leases replace crash-permanent order locks. Order and confirmation writes are atomic. Multiple simultaneous retries converge on the same order and one accepted confirmation in the normal path. SMTP cannot guarantee exactly-once mail delivery across a process crash between server acceptance and marker persistence; the same confirmation can be repeated, without charging again. Dead leases expire after two minutes.
- Stripe Node SDK is pinned to 23.1.0; its installed default API version is 2026-10-28.endive. Nodemailer 10.3.1 and proper-lockfile 4.1.2 are pinned. `tsx` is a production dependency for the host administration commands. The package assembly includes their exact source/alias configuration; no secrets, private release manifest, orders or paid ZIPs are copied.
- Native download/receipt failures now return a no-script accessible recovery page, noindex/no-store/no-referrer, without raw errors or reflected tokens. Five labels/messages have drafts in all nine languages; public failures follow the existing English-only gate. Private forms carry the selected locale. These 40 translated fragments and eight revised generic SEO descriptions are separate from earlier content inventories.
- Generic SEO descriptions no longer promise that the entire website collects no personal information ever. Nine source/draft descriptions refer to the learning/resources offered. The live privacy page discloses adult payment/email/hosting/review processing separately from device-only progress. This is a factual correction, not the final comprehensive SEO/editorial pass.
